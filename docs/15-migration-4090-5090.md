# 15 — 迁移到 4090 / 5090：sm_89 / sm_120 重编译与量化选择

> 事实来源：HANDOVER.md（GB10 sm_120 + unified 121G 部署）、路线 C oneclick llama.cpp-omni 编译经验
> 本文适用：从 DGX Spark GB10 迁到 RTX 4090 或 RTX 5090 独显机

## 硬件参数对比

| GPU | 架构 / SM | VRAM | CUDA Arch 编译标记 |
|---|---|---|---|
| GB10 (DGX Spark) | Blackwell / sm_120 | unified 121G | `-DCMAKE_CUDA_ARCHITECTURES=120` |
| RTX 4090 | Ada Lovelace / sm_89 | 24G（独显） | `-DCMAKE_CUDA_ARCHITECTURES=89` |
| RTX 5090 | Blackwell / sm_120 | 32G（独显） | `-DCMAKE_CUDA_ARCHITECTURES=120` |

**关键推论**：
- 5090 与 GB10 同为 sm_120，**llama-server 二进制可直接复用 GB10 编译产物**（待验证；CUDA/驱动版本需匹配）
- 4090 是 sm_89，**必须重新编译** llama.cpp-omni
- nvidia-smi 在 GB10 上显存字段返回 N/A（unified 架构），4090/5090 是独显，显存监控正常

## 量化档位选择决策树

```
GPU VRAM 24G（4090）   → Q4_K_M 必选（4.7G GGUF + KV 缓存），Q8_0（8.2G）可装但 KV 预算紧
GPU VRAM 32G（5090）   → Q8_0 甜点，F16 可装但 ctx 8192 时 KV 不够宽裕
GPU VRAM ≥48G / unified → F16 最佳（几乎无损，路线 C 实测用户「速度也很快」）
```

**实测对照表**（来自 HANDOVER，GB10 上测得，可作为 5090 的下界参考）：

| 量化 | 文件大小 | 智能主观 | 速度主观 | 备注 |
|---|---|---|---|---|
| F16 | ~16G | 高 | GB10 上卡顿 | 5090 应无此问题（独显带宽远高于 GB10 LPDDR5X） |
| Q8_0 | 8.2G | 中高（甜点） | 流畅 | 路线 C2 + B-cpp 用户默认推荐 |
| Q4_K_M | 4.7G | 肉眼下降 | 极致流畅 | 4090 唯一稳妥选项 |

## llama-server 重编译

### 4090（sm_89，必须重编）

```bash
# 1. 拉源码（上游 tc-mb 的 web-demo 分支）
git clone https://github.com/tc-mb/llama.cpp-omni
cd llama.cpp-omni && git checkout feat/web-demo

# 2. 配置 CUDA arch
cmake -B build \
  -DCMAKE_CUDA_ARCHITECTURES=89 \
  -DGGML_CUDA=ON \
  -DLLAMA_CURL=OFF

# 3. 只编 llama-server target（其他工具不需要）
cmake --build build --target llama-server -j$(nproc)

# 产物：build/bin/llama-server
# 编译耗时：1-2h（取决于 CPU 核数和 CUDA toolkit 版本）
```

### 5090（sm_120，可复用 GB10 产物）

- 方案 A：把 GB10 上编好的 `build/bin/llama-server` 直接 scp 过去，先 `--help` 冒烟验证
  - 前提：5090 机器的 glibc / CUDA runtime 版本与 GB10 编译机兼容（待验证）
- 方案 B：按上面 4090 命令把 `=89` 改成 `=120` 重编一遍，最干净

## 迁移 checklist

1. **clone 本仓库**（`spark-minicpm`）到目标机
2. **装系统依赖**：
   - `cmake` ≥ 3.22
   - `pnpm`（如走路线 C 需要 Vue 前端）
   - `livekit-server` ≥ 1.9（路线 C）
   - Python 3.10 + `venv`
   - CUDA toolkit 对齐 GPU arch
3. **clone 上游仓库**：
   - `OpenBMB/MiniCPM-o-Demo` 的 `Comni` 分支（路线 B-cpp）
   - `OpenSQZ/MiniCPM-V-CookBook`（路线 C）
   - `tc-mb/llama.cpp-omni` 的 `feat/web-demo` 分支
4. **重编 llama-server**（按目标 GPU 选 sm_89 / sm_120）
5. **下载 GGUF 权重**（hf-mirror 或从本机副本拷）
6. **应用 patches**：`bash apply-patches.sh`（本仓库脚本，具体路径待验证）
7. **改 config.json**：模型路径指向下载目录，quant 选对档位
8. **启动**：`bash routes/X/up.sh`（X = b-cpp / c / d）

## 常见迁移失败点（预防）

- **4090 编完跑不了**：八成是 CUDA arch 没传 89，默认会把全量 arch 编进去体积爆炸；明确指定 `=89` 最干净
- **VRAM OOM**：4090 跑 F16 必炸（16G 模型 + KV + vis encoder 轻松超 24G）；老老实实 Q4_K_M
- **pnpm 10 ERR_PNPM_IGNORED_BUILDS**（路线 C）：绕开 pnpm 直接 `node_modules/.bin/vite build`，参考 HANDOVER 2026-05-10 段
- **livekit-server 装 /usr/local/bin 要 sudo**（路线 C）：用 `~/.local/bin/` 无 root 方案
- **sparse-clone 嵌套目录**：路线 C 的 oneclick.sh 首次跑会产出 `WebRTC_Demo/WebRTC_Demo/` 嵌套，手动 build 要进内层
- **Ref audio 路径**：路线 A 的 `config.yaml` `paths.ref_audio` 必须用绝对路径指到 `MiniCPM-o-4_5/assets/HT_ref_audio.wav`（docs/03-pitfalls.md P2）
